Project

A directory of .sql files, one model per file. Nothing is uploaded: the planner runs in this page, and the files are read locally.

Sources and materializations

Without these, columns from those tables cannot be resolved and the planner assumes they changed — which over-selects rather than under-selects.

Anything unnamed is a table. Only incremental models are partition-scopable, so a project with no hints rebuilds every model whole.

A sources.json or materializations.json in the folder is picked up automatically.

Plan

Partition scoping

Models the planner scoped to specific partitions. Each partition becomes its own work item — this is where a rebuild stops being all-or-nothing.

Concurrency waves

Every item in a wave can run at the same time; a wave starts once the one before it finishes. This is the shape of the rebuild, not its duration — nothing here is measured in time.

The work items in execution order. Draining them in # order is always dependency-safe; running a whole wave at a time is the parallel form. Waits on is model-level: an item waits on every in-plan upstream of its model, which stays correct under lookback windows where partition-to-partition edges would not.

State

Fingerprints recording which code has been built. They live in this browser only — a teammate opening this page has their own. Export the file and commit it to share one answer across a team.

Cost is a prediction read off a rate card, in compute units — 1 CU is one full rebuild of one table model. There is no benchmark behind it and no figure on this page is measured in seconds. mCU is the exact integer the planner computed; CU is that divided by 1000 for display.

The planner is Rust compiled to WebAssembly and runs entirely in this page. No SQL, no file and no fingerprint is sent anywhere, because there is nowhere to send it to.
